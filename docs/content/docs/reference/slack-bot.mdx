Part of the [channel adapters](/docs/reference/channel-adapters) family.

Transport: **Socket Mode** (no public URL required). Setup walkthrough: [Add a channel](/docs/guides/add-a-channel).

## Crash recovery correlation

Interruption notices carry opaque Slack message metadata (`typeclaw_recovery`).
Recovery checks every history page in the exact channel or thread and accepts only
the authenticated bot user's matching delivery ID. History read failures are not
evidence of absence. The bot account is revalidated before each recovery send.
Delivery remains at-least-once: deleted or unavailable metadata can lead to a
duplicate notice after an ambiguous send. Ordinary replies are unchanged.
Direct-message workspace coordinates use a sentinel; account identity still comes
from the authenticated team and bot user. Background admission reads that cached
identity without calling Slack, and an unavailable cache leaves the launch
admissible with an unbound recovery record.

## Auth

Two tokens, both stored in [`secrets.json`](/docs/reference/secrets-json):

| Field                         | Value                                  |
| ----------------------------- | -------------------------------------- |
| `channels.slack-bot.botToken` | `xoxb-…` bot token                     |
| `channels.slack-bot.appToken` | `xapp-…` app-level token (Socket Mode) |

CLI: `typeclaw channel add slack-bot` (interactive), `typeclaw channel set slack-bot` (rotate).

<Callout type="warn" title="reactions:write is required">
  The bot token must have the `reactions:write` scope. Without it, Slack returns `missing_scope` on the auto-`:eyes:`
  engage reaction and every `channel_react` call. See the app manifest in [Add a channel](/docs/guides/add-a-channel)
  for the full scope list.
</Callout>

## Own-reaction cleanup

The adapter removes only the authenticated account's reaction with `reactions.remove`, using the original channel, message timestamp, and normalized emoji. `no_reaction` is successful absence. Account rotation blocks cleanup belonging to the old identity; replies do not await cleanup transport. Protected acknowledgments survive temporary cleanup and reboot. The same own-removal contract applies to the [Slack user adapter](/docs/reference/slack).

### Exact attachment selection

`attachment_id` is message-local: two messages can both contain attachment `#1`.
Both live messages and history expose `file_id=F…` in each Slack attachment
placeholder, so the selector is visible even when historical messages reuse `#1`.
For an older attachment, read history first and pass its exact Slack `file_id`
to `channel_fetch_attachment` or `look_at_channel_attachment` alongside
`attachment_id`. An unseen ID is rejected, not replaced by another file.
Downloads and visual reads identify the selected Slack file in success and
download-error results.
A current request's own attachment wins; observed old scrollback cannot shadow a
newer attachment discovered through history, and queued future messages cannot
retarget an in-flight read.

HTML email originals are valid attachments. HTML returned instead of a declared
PDF/image, or a sign-in form returned for an HTML original, remains an error.
The downloader retains its trusted-redirect and streaming-size limits.

Plugins reading raw order documents should declare internal readers
`ephemeral: true`. The runtime creates an in-memory session manager for that
trusted declaration; model payloads cannot change it. Raw source pages then do
not enter the ordinary persisted session transcript. A plugin can require the
matching `createSubagentSessionManager` export before registering such a reader;
older runtimes that do not support it must not silently persist the source.

## Thread stickiness

Replies in the same Slack thread route to the same session. New top-level messages start fresh sessions. The `app_mention` event is required for the bot to hear mentions in channels where it is not a member.

Outbound `thread` must be the parent message's exact Slack `ts` string (for example, `1700000000.000100`), including all six digits after the decimal. Malformed IDs are rejected before a text post or file upload. Slack timestamps are message IDs, not decimals: do not round or pad a truncated ID.

The bot responds to a Slack message at most once. If it engaged the original, later edits never trigger it again, including after a restart, and a copy of the message routed into a mention thread does not either. If it only observed the original, an edit that adds a bot mention can engage it once. Two shapes qualify. One is a raw `message_changed` event whose previous text lacks an explicit `<@bot>` or `<!here>` / `<!channel>` / `<!everyone>` mention, whose new text has one, and which carries Slack's `edited.ts`. The other is an `app_mention` with a valid edit marker that addresses the bot; Slack may deliver only this event in channels the bot hasn't joined. It is accepted as a first engagement, not as proof that the edit added the mention. The response keeps the original message `ts` and the message author. Typo and other content edits (including in DMs), edits to an already-mentioned message, mention removal, unfurl or metadata-only updates and flattened `message` copies carrying `edited` are dropped. A known edit that contains a slash command, a claim code or a thread command (`!help`, `!stop`, `!reload`, `!restart`) is dropped before any handler runs. Other `!word` text stays an ordinary message. An `app_mention` without an edit marker can't be told apart from an original, so it follows the original path, commands included; command handling is not exactly-once. Retry deliveries and the matching `message` / `app_mention` pair are deduplicated to one admission.

Suppressed retries still associate their timestamp and client-message identities with the same cached delivery, so a resend under another timestamp cannot trigger a second mentioned delivery.

## Plugin edge hooks

[`channel.message.observed`](/docs/reference/plugin-api#channel-edge-hooks) gives trusted plugins a deep-frozen snapshot of raw Socket Mode `message` receipts after ack, before wake filtering or deduplication. It includes non-mentions, edits, deletes, bot/self messages and duplicates; `app_mention`-only events are excluded. Observation is best-effort, does not open a model session and adds no Slack scopes or durable storage.

[`channel.outbound.before`](/docs/reference/plugin-api#channel-edge-hooks) transforms application text on sends, captions, edits and existing runtime output. Thread `!cmd` responses also pass through it. When a reviewer is installed, native slash commands ack immediately and return the reviewed response ephemerally via a validated Slack response URL; unavailable/unsafe URLs retain the original ack response. Hook failures/timeouts retain the previous text. No hook can change destinations, permissions or turn accounting, and no hook re-enables suppressed notices.

## Slash commands

`/help`, `/stop`, `/reload`, `/restart`. Thread `!cmd` syntax also works.

## Config

```json
{
  "channels": {
    "slack-bot": {
      "enabled": true,
      "engagement": {
        "trigger": ["mention", "reply", "dm"],
        "stickiness": { "perReply": { "window": 900000 } }
      },
      "history": {
        "prefetch": {
          "thread": { "head": 3, "tail": 10 },
          "channel": { "tail": 10 }
        }
      },
      "quotedReply": { "enabled": true, "queueDelayMs": 10000 }
    }
  }
}
```

All fields above are shared across adapters. No adapter-specific extensions exist for `slack-bot`. Credentials live in [`secrets.json#channels.slack-bot`](/docs/reference/secrets-json).

## Watching without mentions

Add a workspace ID and channel ID to `engagement.watchChannels` to wake the agent on new messages in that channel and its threads, without a mention.

```json
{
  "channels": {
    "slack-bot": {
      "engagement": {
        "watchChannels": [{ "workspace": "T0123456789", "chat": "C0123456789" }]
      }
    }
  }
}
```

Both IDs must match exactly; channel and workspace names are not accepted. Omit the list or use an empty array to keep the existing engagement rules. Changes take effect on `reload`.

The agent uses its monitoring instructions and conversation context to decide whether to reply or act. It can stay silent with `NO_REPLY` or `skip_response`. Watching does not grant `channel.respond`; edit filtering, deduplication and the peer-bot loop guard still apply.

The bot must belong to the channel, and the Slack app needs the corresponding message event subscriptions and read scopes. Watching does not expand the events Slack delivers.
